# JustGo Core-16 — مترجم الكتل وذاكرة الترجمة

## القرار

لن يولّد JustGo شيفرة x86 أصلية في المتصفح، ولن يحاول تجاوز حواجز المتصفح. بدلاً من ذلك سيحوّل **كتلة تعليمات ضيف محدودة** إلى دالة TypeScript آمنة ومغلقة على حالة CPU وناقل الذاكرة، ثم يحتفظ بها في ذاكرة ترجمة مرتبطة بعنوان البداية وبصمة صفحات الشيفرة وحالة CPU ذات الصلة. هذه ترجمة ديناميكية مبسطة، وليست ادعاءً بأنها بديل كامل لـQEMU TCG.

توضح وثائق QEMU أن كتل الترجمة الصحيحة تسجل حالة CPU المؤثرة على تفسير التعليمة، وأن تغيير تلك الحالة يفرض إنشاء كتلة جديدة. كما أن الشيفرة ذاتية التعديل تتطلب إبطال الكتل المرتبطة بالصفحة المتغيرة.[1]

## عقد الكتلة في المرحلة الأولى

| الحقل | الغرض |
|---|---|
| `startPhysical` | عنوان الكتلة الفيزيائي عند الترجمة. |
| `endPhysical` | أول عنوان بعد الكتلة؛ لا تتجاوز المرحلة الأولى حدود صفحة 4KiB. |
| `modeKey` | بصمة CS وخصائص real-mode الحالية التي تؤثر على فك الشيفرة. |
| `pageVersions` | إصدارات صفحات الشيفرة المطلوبة لإبطال صحيح بعد الكتابة. |
| `run` | دالة مغلقة تنفذ التعليمات المدعومة أو تعيد التحكم إلى المفسر عند حاجز. |
| `exit` | سبب الخروج: قفز أو مقاطعة أو I/O أو تعليمة غير مدعومة أو حد الخطوات. |

تظل الحواجز — مثل I/O والمقاطعات والقفز غير المباشر والكتابة إلى صفحة شيفرة — نقاطاً يعود فيها المحرك إلى الحلقة الأساسية. ذلك يتوافق مع مبدأ QEMU بأن الحلقة الرئيسية تعيد فحص المقاطعات وحالة المعالج عند الخروج من كتلة.[1]

## ترخيص وسيط Windows

تتيح Microsoft تنزيل أداة إنشاء وسائط وISO لـWindows 10، لكنها تنص صراحةً على الحاجة إلى ترخيص لتثبيت Windows 10.[2] لا يعني توفر التنزيل منح ترخيص مجاني. لذلك لا يحمل JustGo وسيط Windows، ولا يجلب مفتاحاً، ولا يخزّن مفتاحاً، ولا يرفعه. إن أضيف اختيار محلي لاحقاً، فسيقرأ المستخدم ملفه محلياً فقط ويحتفظ بحق استخدامه.

إذا أُضيف حقل مفتاح التنشيط في الواجهة، فسيكون اختيارياً ويعيش في ذاكرة الصفحة فقط إلى أن ينهي المستخدم الجلسة أو يمسح الحقل. لا تحفظ القيمة في `localStorage` أو IndexedDB أو السجل أو التحليلات، ولا ترسل في طلب شبكي، ولا تتحقق منها JustGo، ولا تشغّل أي برنامج Windows خاص. عدم إدخال قيمة لا يغير تجربة Core-16 أو بيئة الاختبار الحالية.

### نتيجة البحث الرسمي

وجدنا مساراً رسمياً محدوداً: توثق Microsoft أن **تقييم Windows 10 Enterprise لمدة 90 يوماً** متاح عبر Evaluation Center، وتصفه صراحة كاختبار للمؤسسات لتجارب النشر والتوافق والميزات.[3] هذا يمنح حق تقييم مؤقت وفق شروط Microsoft، ولا يمنح حق إعادة توزيع الصورة أو تشغيلها كخدمة عامة دائمة أو تضمينها في JustGo. وتوضح صفحة تنزيل Windows 10 الرسمية أن إنشاء وسائط التثبيت العادية يتطلب ترخيصاً.[2]

إن استخدم المستخدم تقييم Microsoft، يبقى الاختبار محلياً، ويختار المستخدم الوسيط بنفسه، ولا يرفعه JustGo أو يحتفظ به أو يرسله إلى أي خدمة. كما أن توافق المحرك يبقى شرطاً منفصلاً؛ صلاحية التقييم لا تجعل Core-16 قادراً على إقلاع Windows 10.

> «To get started, you will first need to have a license to install Windows 10.» — Microsoft [2]

## حدود Windows 10

Core-16 لا يقدّم 386 protected mode أو paging أو 64-bit أو BIOS/ACPI/PCI/VGA متكاملة. لهذا لا تشكل إضافة cache للكتل وعداً بإقلاع Windows 10؛ إنما هي خطوة صحيحة لقياس فرق أداء النواة وفحص صحة الإبطال قبل أي توسيع معماري.

## قياس أولي للكتل

في بيئة التطوير الحالية نفذ معيار حقيقي كتلة خطية من 64 تعليمة (`63 × NOP + HLT`) عبر 2,000 تشغيل، أي 128,000 تعليمة. استغرق المفسر **21.16ms** ومسار ذاكرة الكتل **14.96ms**، بنسبة **1.41×** في هذا الحمل المحدد، مع 1,999 إصابة في الذاكرة المؤقتة بعد أول ترجمة. هذا ليس ادعاءً بتسريع شامل: الكتلة لا تتضمن قفزات أو I/O أو مقاطعات أو كتابة ذاتية، وهذه كلها حواجز مقصودة في المرحلة الأولى.
