# JustGo — معالم النمو وعقود التوسع

> **المبدأ:** عدد الأسطر نتيجة للتنفيذ والاختبارات والوثائق والأدوات، وليس هدف قبول مستقل. لا ينتقل JustGo إلى معلم أعلى ما لم تضف كل وحدة عقداً قابلاً للاختبار وقياساً يمكن إعادة إنتاجه.

## معيار القبول لكل وحدة

| حقل | المطلوب |
|---|---|
| العقد | invariant قابل للصياغة والفحص، مثل ترتيب interrupt أو حد عنوان أو سياسة خصوصية. |
| التنفيذ | وحدة مستقلة بمسؤولية ضيقة وواجهات typed. |
| الاختبار | اختبار وحدة أو تكامل يمر في `pnpm check`. |
| القياس | عدّاد، benchmark أو replay equality لا يتطلب وقتاً جدارياً داخل trace. |
| الحدود | ما لا تدعمه الوحدة بعد، حتى لا يتحول الاسم إلى ادعاء توافق. |
| المصدر | لأي corpus أو firmware أو أصل كبير: رخصة، رابط، SHA-256 ومسار تخزين خارج Git عند الحاجة. |

## معالم الحجم الوظيفي

| المعلم | المخرجات المطلوبة | شرط الخروج |
|---|---|---|
| **5K** | Core-16، ذاكرة، ROM، PIT، PS/2، block-cache وtests أساسية | تطابق interpreter/cache وإقلاع تشخيصي محدود. |
| **20K** | Core-64 المحدود، PML4، framebuffer، scheduler، input queue، WebGPU/Canvas abstraction | trace حتمي يربط input→CPU→PIT→video واختبارات fallback. |
| **60K** | replay مستقل، address forms، IDT delivery، PIC/CMOS، أدوات trace وتقارير قياس | replay يحدد أول divergence، وتعليمات/استثناءات إضافية موثقة. |
| **200K** | storage controller محلي، corpus مرخص، differential fixtures وأجهزة أوسع | كل corpus case يحمل مصدره وترخيصه ونتيجته القابلة للإعادة. |
| **500K** | فروع CPU وأجهزة وتحقق تفاضلي وتوثيق generation tooling ناضج | تغطية موزعة، أدوات توليد مدققة، تقارير أداء وحدود توافق واقعية. |

## المصدر التنفيذي

الفهرس ليس وثيقة معزولة: `src/lab/contract-catalog.ts` يعرّف المعالم والوحدات وحالة النضج والاختبار والقياس. يختبر `tests/contract-catalog.test.ts` سلامة هذا الفهرس كي لا تصبح خطة النمو قائمة شعارات غير قابلة للتنفيذ.

لا يعني أي معلم من هذه المعالم أن JustGo يشغل Windows أو Linux كاملاً. لا يُعلن التوافق إلا بعد اختبار وسيط مشروع محدد، ضمن الأجهزة والتعليمات المطلوبة، وبنتيجة منشورة قابلة لإعادة التحقق.
